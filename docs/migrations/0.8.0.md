# OpenCollab 0.8.0 migration guide

This record covers 0.7.x → 0.8.0. The [Base and Single2 guide](../single2.md)
and [package guide](../../opencollab/README.md) describe current behavior.
Patch-release fixes and test/distribution changes are recorded in the
[0.8.x release notes](../../CHANGELOG.md#083---2026-10-01).

## Breaking changes

### Base replaces Single as the default agent

0.8.0 removes the legacy Single implementation and prompt. Base becomes the
standalone default and maps to Single2. Existing code can still call `agent`,
but it now selects a different implementation:

| Selection | Meaning in 0.8.0 |
| --- | --- |
| Omitted profile; `base`, `default`, or `single` | Follow Base → Single2 |
| `single2`; `agent2(...)` | Select Single2 explicitly |

```python
result = await client.agent(task, profile="base")
result = await client.agent(task, profile="single2")
result = await client.agent2(task)
```

For reproducible comparisons, record the concrete `metrics["agent_profile"]`
with the source revision. `opencollab.profiles.BASE_PROFILE` and
`resolve_profile_name()` expose the mapping. New implementations register in
`bootstrap/agent_profiles.py`; Base follows its chosen factory while an explicit
implementation name keeps selecting that factory. Factories supply the prompt,
tools, shaper, safety wrapper, and default limits.

### Single2 behavior to review

The 0.8.0 profile uses the static repair prompt evaluated on SWE-Mix-80, a
200-step default, and the ordered tools `bash`, `file_read`, `file_write`,
`apply_patch`, `git_diff`, `grep`. Bash retains up to 10,000 characters per
stream; oversized tool results keep head and tail within a 16,000-character
context cap. Recursive searches at container root are rejected while
workspace-scoped searches remain available.

Bash requires process isolation. For deliberate host execution, supply explicit
tools with `headless=False`; the local filesystem tools remain usable without
that permission:

```python
from opencollab.tools import builtin_tools, profile_tool_limits

tools = builtin_tools(
    "bash", "file_read", "file_write", "apply_patch", "git_diff", "grep",
    headless=False,
    limits=profile_tool_limits("base"),
)
result = await client.agent(task, tools=tools)
```

`profile_tool_limits()` returns a copy for inspection. Caller-supplied tool
instances retain their own settings.

### Explicit token and step limits behavior

With `OPENCOLLAB_UNBOUNDED_LIMITS=true`, explicit standalone `budget` and
`max_steps` remain effective for Base/Single2; omitted limits are unbounded.
Integrations must test both paths rather than assume profile defaults replace
their finite authorization. Workflow limit handling remains a separate contract;
see the [current runtime reference](../evaluation-runtime.md#limits-and-deadlines).

## Profile selection in workflows

Pass `agent_profile="base"` or `"single2"` to `client.workflow(...)` to select
the same implementation for every role. Omission retains role-defined
configuration. Role duties and explicit tool permissions still take precedence;
a profile does not grant additional coordination or shell tools. Completed runs
record the concrete profile. See the [current workflow example](../../opencollab/README.md#workflow-authoring)
and [profile composition rules](../single2.md) for full usage.

## Upgrade steps

1. Install the intended verified release, for example:
   ```bash
   python -m pip install "opencollab @ git+https://github.com/RISE-X-Lab/OpenCollab.git@v0.8.0"
   ```
   A wheel from its GitHub release is the other supported installation path.
2. Review every omitted, `single`, and `default` profile selection for the change
   to Base/Single2. Pin `single2` when the concrete implementation matters.
3. Test tools, host-shell authorization, explicit and omitted limits, workflow
   profile selection, and returned execution/verification outcomes.
4. If using Eval, its [0.8.0 dependency metadata](https://github.com/RISE-X-Lab/OpenCollab-Eval/blob/v0.8.0/pyproject.toml)
   requires OpenCollab `>=0.8,<0.9`. Keep exact recorded revisions for old results.
5. For contributor scripts, 0.8.1 moved tests into behavior directories. Use the
   [current test map](../../CONTRIBUTING.md#find-and-run-the-relevant-tests)
   instead of hardcoding the previous layout.

For upgrades from 0.6.x, apply the [0.7.0 migration](0.7.0.md) first.
