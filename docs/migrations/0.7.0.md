# OpenCollab 0.7.0 migration guide

This record covers 0.6.x → 0.7.0 and the later source changes described below.
Use the current
[Duo](../duo.md), [runtime](../evaluation-runtime.md), and
[package](../../opencollab/README.md) guides for later APIs. The
[release notes](../../CHANGELOG.md#070---2026-09-14) retain the feature and fix list.

## Breaking changes

### Native Bash testing replaces `run_tests`

Replace `run_tests` with `bash` in tool lists and remove a duplicate if Bash is
already present. Remove `tool_limits.run_tests`; use
`tool_limits.bash.max_output_chars` for shell output caps. Prompts should request
the repository's native command, selected targets, exit status, and output.

```python
from opencollab.tools import builtin_tools

tools = builtin_tools("file_read", "bash", "git_diff")
```

The removed tool's runner selection, parsers, GREEN/RED verdicts, evidence cache,
and repeated-failure nudges are gone. Bash does not synthesize a verified verdict.
Unknown `run_tests` requests fail; there is no silent alias from a tests-only
permission to general shell access. Migrate saved runs and external workflows
before resuming on this version, or retain their original installation.

#### Test command timeouts

Bash defaults to **120 seconds**; the removed `run_tests` default was **300**.
Supply a per-call `timeout=300` to preserve that allowance, or a longer value for
suites that need it. For example, these Bash tool-call arguments allow ten minutes:

```python
test_call = dict(command="python -m pytest -q", timeout=600)
```

#### Execution permissions

Bash requires process isolation unless the caller explicitly authorizes host
execution. Command confirmation, output bounds, timeout, and cancellation remain
in force. Prebuilt teammates inherit the entry-agent shell policy. Dynamically
spawned children still require process isolation in interactive mode unless
`--allow-local-child-shell` (or `allow_unisolated_child_shell=True` on the
scheduler builder) authorizes host execution. For the demo:

```bash
./scripts/demo_team_issue.sh --allow-local-child-shell
```

The old `--allow-local-child-tests`, `allow_unisolated_tests`, and
`allow_unisolated_child_tests` settings are removed; none grants shell access
implicitly. Prefer an isolated environment for unattended commands.

#### Verification integrations

`VerificationTool` remains a public structural protocol. At 0.7.0 no built-in
implemented its `verified_targets` property, so integrations needed a custom
verifier or their earlier runner. Current releases offer the explicit
[`evidence_tools()` wrapper](../test-evidence.md). A zero exit, help output, or
zero collected tests alone does not verify the requested tests. Benchmark scoring
and external runners were unaffected by this tool removal.

## Post-0.7.0 source changes

The `v0.7.0` tag accepts workflow functions/specs and does **not** include the
built-in Duo or SDK name discovery. Those arrive at
[`91a33979`](https://github.com/RISE-X-Lab/OpenCollab/commit/91a33979ca711924e442b6b09cd9e51cec03dabc), after the tag,
and are included in `v0.8.0`. Use a revision containing that change for the
following API; installing `v0.7.0` alone does not provide it.

### Duo workflow shell execution requires opt-in

A caller migrating a local Duo implementation with unrestricted shell access must pass
`allow_unisolated_shell=True`. Container-backed calls may omit it and keep the
default process-isolation requirement.

```python
from opencollab import OpenCollab

client = OpenCollab("/path/to/workspace")
result = await client.workflow(
    "duo",
    {"goal": "Fix the bug and run its tests.", "allow_unisolated_shell": True},
    budget=1_000_000,
    artifacts="artifacts/duo-run",
)
```

### Public integration surface

| Added surface | Migration relevance |
| --- | --- |
| Installed Duo and named workflow discovery | CLI and SDK combine built-ins with `workflows/` or `OPENCOLLAB_WORKFLOWS_DIR`; no copied Duo module is needed. |
| `get_builtin_workflows()` / direct workflow functions | At introduction the registry contained only Duo; later releases add workflows. Avoid carrying that historical exact-set assumption into current code. |
| Evaluation runtime (already in v0.7.0) | Candidate isolation, explicit unbounded limits, model/snapshot inspection, and durable request observations are public integration capabilities. |
| `opencollab.patches` | `patch_entries`, `patch_paths`, and `split_patch_blocks` provide shared Git patch parsing. |

The original Duo used prompt revision 4 and paged candidate evidence, with Git
and full-environment candidate backends. Reproducing that condition requires its
original revision; the current Duo guide describes later selection behavior.

## Upgrade steps

1. Select and test the intended release or source revision. Keep old saved artifacts
   with their original version until their tool lists and permissions are migrated.
2. Replace `run_tests` and its prompt/limit settings; check the changed timeout.
3. Authorize host shell execution explicitly where intended, including dynamic
   children, or supply process isolation.
4. Test actual target execution and lifecycle/cleanup outcomes in the integration.
5. If using Eval, its [0.7.0 dependency metadata](https://github.com/RISE-X-Lab/OpenCollab-Eval/blob/v0.7.0/pyproject.toml)
   requires OpenCollab `>=0.7.0,<0.8`. That range alone does not prove a later
   source API exists. Preserve the exact recorded pair for old results.

Continue with the [0.8.0 migration](0.8.0.md) for Base and Single2.
